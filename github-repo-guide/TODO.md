# 待辦功能

## 自動跳到下一步

> 狀態：**已完成**（2026-10-15 記錄，2026-10-18 完成）
> 實作：步驟的 `doneWhen` 和 target 的 `done: true` 在 `courses.js`，判斷邏輯在 `panel.js`。
> GA、GSC、GTM 的步驟還沒有加自動判斷（Google 的網址規則還沒確認），需要時可以照同樣方式加。
> 靈感：Tango 的 Guidance／Guide Me，點了框起來的按鈕就自動進到下一步。

### 想要的效果

現在每一步做完都要手動按「下一步」。改成**偵測到使用者已經完成這一步，就自動前進**，用起來更順。

### 兩種偵測方式

1. **網址變了**：到了下一步該在的頁面，就代表這一步完成了。例如在建立 repo 頁面按下 Create repository 後，網址變成 repo 首頁。
2. **點了框起來的按鈕**：使用者點了這一步標示的按鈕，就前進。例如點了 Settings 分頁。

### 各步驟怎麼判斷完成

| 步驟 | 完成的判斷 | 方式 |
|---|---|---|
| 打開「建立 repo」頁面 | 網址變成 `/new` | 網址 |
| 取 repo 名稱 | **不自動**（要打字，不知道打完了沒） | — |
| 設成 Public、加 README | **不自動**（同上） | — |
| 建立 repo | 從 `/new` 跳到 repo 首頁 | 網址 |
| 打開上傳頁面 | 網址變成 `/帳號/repo/upload/...` | 網址 |
| 拖曳檔案並 Commit | 從上傳頁面回到 repo 首頁 | 網址 |
| 新增首頁檔案 | 網址變成 `/帳號/repo/new/...` | 網址 |
| 貼上網頁內容 | **不自動**（要打字、貼上） | — |
| 儲存檔案（Commit） | 從新增檔案頁面跳到檔案頁面或 repo 首頁 | 網址 |
| 打開 Settings | 網址變成 `/帳號/repo/settings` | 網址 |
| 打開 Pages 設定 | 網址變成 `/帳號/repo/settings/pages` | 網址 |
| 開啟 GitHub Pages | 點了 Save | 點擊 |
| 確認部署完成 | 網址變成 `/帳號/repo/actions` | 網址 |
| 刪除檔案 | 網址變成 `/帳號/repo/delete/...` | 網址 |
| Render 各步驟 | 點了框起來的按鈕（Render 的網址規則還不確定） | 點擊 |
| VS Code 的步驟 | **不自動**（在 VS Code 裡做，擴充功能看不到） | — |

### 實作想法

- 在每一步的設定裡加一個 `doneWhen`（完成條件），例如 `doneWhen: () => PAGES_SETTINGS.test(path())`。
- 在 `scan()` 裡檢查目前這一步的 `doneWhen`，成立就呼叫 `setState({ step: state.step + 1 })`。
- 點擊偵測：在框起來的按鈕上監聽 `click`，或把 `doneWhen` 設成「點了某個按鈕」。
- 一次最多只跳一步，避免連續跳過好幾步。

### 要注意

- **要讓使用者知道跳了**：自動前進時顯示一行小提示，例如「✅ 已完成，自動前往下一步」，不然會覺得面板自己亂跳。
- **不要誤跳**：只有在「這一步的頁面 → 下一步的頁面」這種轉換時才跳。如果使用者本來就在亂逛，例如直接打開別的 repo 的 Settings，不應該跳。
- **可以關掉**：面板上加一個「自動跳下一步」的開關，存在 `chrome.storage` 裡。
- 「上一步」照常可以用。按了上一步之後，不要馬上又被自動跳回來（例如等網址改變後才重新判斷）。
